# 2025–2026 多模态监督与 KV 选择：检索和核查记录

日期：2026-11-03（Asia/Shanghai）。服务于[阅读计划](../论文阅读.md)和[第一版设想](../MLLM视觉KV选择_第一版研究设想.md)。这是可追溯的研究记录，不是全网覆盖证明。

## 1. 检索范围和实际限制

目标分成三条线：视觉 KV 的缓存机制与教师标签；视觉区域/语义/注意力监督的学习选择器；压缩后行为蒸馏与训练成本。另从反方寻找“文本注意力不等于视觉重要性”和“已有类似监督”的证据。

Google、Bing、export.arxiv.org API 在本次云环境经代理返回 CONNECT 403。没有绕过代理，也没有申请用户密钥。GitHub 搜索、raw 内容与 git 克隆可用。对原文件作者仓库进行复查，再用多个独立公开索引扩展候选，并沿作者代码的引用/acknowledgment 追踪。这个路线得到有用证据，但存在不公开代码/仅托管论文网站的漏检风险。

采用 deep-research 技能的研究问题、分视角检索、引用核查与反方检视；独立检索发现后集中综合。没有把索引分类标签当成冻结状态、监督机制或会议录用证据。

## 2. 检索词与两轮收敛

## 3. 关键事实与原始证据

### SparseMM：视觉概念响应与真实区域校准

题名与作者见[官方 citation](https://github.com/CR400AF-A/SparseMM#citation)：Jiahui Wang、Zuyan Liu、Yongming Rao、Jiwen Lu，2025，2506.05344。

- [框到 patch、生成概念匹配及 head 命中](https://github.com/CR400AF-A/SparseMM/blob/main/visual_head/llava_visual_head.py#L56-L118)：`hit_score` 在 top-attended patch 命中 bbox 时按 `1/len(bbox_token_idx)` 加分。
- [COCO 对应路径](https://github.com/CR400AF-A/SparseMM/blob/main/visual_head/llava_visual_head_coco.py#L43-L135)。
- [离线 1000 样本校准与写入 JSON](https://github.com/CR400AF-A/SparseMM/blob/main/visual_head/llava_visual_head.py#L162-L173)。
- [固定 head 先验与预算](https://github.com/CR400AF-A/SparseMM/blob/main/sparsemm/sparsemm_utils.py#L481-L493)。
- [真实 K/V gather](https://github.com/CR400AF-A/SparseMM/blob/main/sparsemm/sparsemm_utils.py#L584-L600)；[当前 prefill 用完整 K/V、cache 写入压缩 K/V](https://github.com/CR400AF-A/SparseMM/blob/main/sparsemm/qwen_model.py#L79-L89)。
- 核查 checkout：`33f2f0ab96d1d99516bcd2092caccab60516ff2c`。

解释边界：这是含标注的离线校准，不是训练 neural gate；全局 head 先验与输入相关位置排序必须分开。不把“只有少量 visual heads”的作者实验观察当所有模型的固定比例。

### GlimpsePrune：监督小型视觉选择器

题名、作者及初稿/修订时间见[官方 README](https://github.com/HVision-NKU/GlimpsePrune)。2025 初稿 2508.01548；作者报告修订版 TCSVT 2026，DOI 10.1109/TCSVT.2026.3702147；会议/期刊状态未独立核对。

- [默认 Qwen7B YAML](https://github.com/HVision-NKU/GlimpsePrune/blob/main/train_configs/qwen2_5_7b_gp/qwen2_5_7b_gp.yaml)：`MaskLoss`、Dice 1、BCE 0.1，`loc_weight=1`、`le_weight=1`，KD/reward 关闭，`ori_attn_supervision=false`。
- [训练实现](https://github.com/HVision-NKU/GlimpsePrune/blob/main/train_qwen_gp.py)：MaskLoss（约 316 行起）、loss（约 1576 行起）、基础参数冻结与新增模块解冻（约 1995 行起）。
- [glimpse 与 VIP 模块](https://github.com/HVision-NKU/GlimpsePrune/blob/main/transformers_gp/models/qwen2_5_vl/model_gp.py)；[启动脚本](https://github.com/HVision-NKU/GlimpsePrune/blob/main/scripts/train_qwen_gp.sh)。
- 作者报告基础版 20K GQA、单 A100 少于一小时；GP+ 可选配方 4×80GB A100 并使用约 48GB reward model，约 24 小时。只作为分版本声明，不作本机成本保证。

解释边界：原/default 用区域 mask 与辅助 CE，不能说成原版靠 KD/RL；VIP 依赖问题/中间上下文，不等价于无问题的离线逐 KV gate。

### VisionSelector：答案监督和自身选择约束

题名、作者、2025 初稿与作者声明 ACM MM 2026 见[官方 README](https://github.com/JulietChoo/VisionSelector)。

- [冻结脚本](https://github.com/JulietChoo/VisionSelector/blob/main/qwen-vl-finetune/scripts/sft_7b.sh#L31-L46)：vision/mlp/llm=False，compressor=True。
- [自身 hard Top-K 标签构造](https://github.com/JulietChoo/VisionSelector/blob/main/qwen-vl-finetune/compression_method/selector_model.py#L158-L173)。
- [答案 CE 与 mask BCE](https://github.com/JulietChoo/VisionSelector/blob/main/qwen-vl-finetune/compression_method/selector_model.py#L292-L311)。
- [推理时选择视觉特征](https://github.com/JulietChoo/VisionSelector/blob/main/qwen-evaluation/token_compression/selector_model.py#L179-L194)。

解释边界：12.85M 参数是作者报告；自身 hard mask 不是视觉教师真值；减少进入 LLM 的 tokens，不是 cache-only 干预；参数冻结不代表不需通过冻结 LLM 回传梯度。

### VisCo：新 memory KV 与答案 CE

[官方 README](https://github.com/Zyvpeng/VisCo)核对作者 Yupeng Zheng、Kai Zou、Bin Liu、Nenghai Yu；2607.12756；作者声明 ACM MM 2026。

- [Qwen 训练脚本](https://github.com/Zyvpeng/VisCo/blob/main/train/train_qwen2.py)与[LLaVA 脚本](https://github.com/Zyvpeng/VisCo/blob/main/train/train_llava15.py)：rank 与目标模块、memory 数量。
- [Qwen 实现](https://github.com/Zyvpeng/VisCo/blob/main/model/visco_qwen2.py)：`disable_adapter()`、传入 memory `past_key_values`、shifted labels 与 `CrossEntropyLoss`。
- 核查 checkout：`f5b3e039a68909bb5870a8e3a4e3b8a7aaeab949`。

解释边界：代码中存在多个实验类/路径，报告具体默认脚本而非笼统声称每条路径都相同。autoencoder 名称不能代替对 loss 的检查。

### VisPruner、MixKV 与 VFlowOpt：反证与非学习约束

- [VisPruner 官方资料](https://github.com/Theia-4869/VisPruner)：2025 标题与作者列表不同于同 ID 的早期 FasterVLM。明确分析 text–visual attention 不是理想指标，使用视觉显著性和相似性去重。只据作者资料说明，不将其等同于对 KVzip 的直接反证。
- [MixKV 具体混合与 gather](https://github.com/xuyang-liu16/MixKV/blob/main/mixkv/mixkv_utils.py#L288-L397)：attention、value norm 与 key similarity/diversity，随后真实 gather；[Qwen 路径](https://github.com/xuyang-liu16/MixKV/blob/main/mixkv/qwen2_self.py#L69-L89)。作者/日期见仓库 citation，2510.20707；作者声明 ICLR 2026。
- [VFlowOpt 作者资料](https://github.com/sihany077/VFlowOpt)；[优化实现](https://github.com/sihany077/VFlowOpt/blob/main/src/lmms_eval-0.2.4/lmms_eval/models/llava_ov_opt_all.py)：约 584–600 行取完整/裁剪路径最后一个 prompt token 的末层 hidden cosine；约 612–705 行 Bayesian search，`n_calls=100`。是无梯度离线策略搜索，不是像素/视觉特征重建监督 gate。

### LT-OPD、SCOPD 与 PixelPrune：监督与训练成本

- [LT-OPD README](https://github.com/Yrxxxxxxxx1007/LT-OPD)核实 Junxian Li 等作者、2609.32353、2026-09 发布；student rollout + frozen full-token teacher、预算 curriculum；默认 8 GPU 全参数学生训练（含 ViT/merger）；最新分支还加 merge。冻结教师不等于冻结学生。
- [SCOPD README](https://github.com/Enmingzz/scopd-repo)和[训练契约](https://github.com/Enmingzz/scopd-repo/blob/main/docs/TRAINING.md)核实 2026-09 公开实现、EMA full-context teacher、forward KL、LoRA，以及 SCOPD+ 在 10%/11% 预算下测响应位置敏感性。**论文作者名单/完整元数据未在官方 README 独立核实；阅读计划仅将其作为公开实现/训练契约来源，不作完整书目核验。**
- [PixelPrune 官方 citation](https://github.com/OPPO-Mente-Lab/PixelPrune)：作者为 **Nan Wang、Zhiwei Jin、Chen Chen、Haonan Lu**，2604.00886。二手索引误列其他作者，已经纠正。
- [PixelPrune 可选训练](https://github.com/OPPO-Mente-Lab/PixelPrune/blob/main/training/README.md)、[配置](https://github.com/OPPO-Mente-Lab/PixelPrune/blob/main/training/configs/training_config.json)、[损失实现](https://github.com/OPPO-Mente-Lab/PixelPrune/blob/main/training/utils.py)：存在 full-image teacher / KL 适配基础设施，但默认配置走 CE；主方法无可训练参数。不能将可选基础设施写成论文已证明的主要贡献。

### 近期缓存基线

- [BACON](https://github.com/ryu1ion/official_BACON)：作者与日期有 README/引用核对；2606.14782；作者声明 EMNLP 2026。窗口、last-query attention、层内 coherence、层间 persistence；training-free，不是 learned teacher。
- [HybridKV](https://github.com/KevinZeng08/hybrid-kv)：作者 citation 2026、2604.05887；static/dynamic heads、text-prior pruning/chunk retrieval。会议标签仅二手资料，未写入本轮确定结论。
- [PrefixKV](https://github.com/THU-MIG/PrefixKV)：作者与 2412.03409 核对；作者声明 NeurIPS 2025，初稿 2024。profile/search 与参考输出评估不等于训练蒸馏。

## 4. 未进入核心结论的线索与遗漏

- TRAG 官方仓库描述 response-to-vision attention、entropy-adaptive KL，但没有完整作者 citation 和训练代码；未作为正式核验论文支持结论。待能访问全文/元数据后优先补查。
- Video-XL-Pro 是 2025 reconstructive compression 线索，但本次可访问 README 未充分说明具体重建目标和 loss；不据标题写成已核实的图像/视觉 embedding 重建。
- ViCToR 有视觉 token reconstruction 线索，但官方 citation 为 2024；仅代码 2025 发布不能自动满足本轮年份条件。若进一步核实 2025 正式版本，可补入背景。
- SToRM 目前只取得二手线索，不进入正式表。
- 没有完成全量 2026 会议目录、所有反向引用、全部全文或 GPU 复现；结果不证明某方向不存在先行工作。

## 5. 本轮修正了什么

1. 将问题从“训练型 MLLM 压缩有哪些”收敛为“视觉标签、原 KV 与低成本训练怎样连接”。
2. 补入 SparseMM、GlimpsePrune、VisionSelector，直接回应原计划缺少视觉监督的问题。
3. 将 VisCo 的 memory KV、token 选择与 cache-only 三类干预分开；将 full-visual teacher 监督与主干是否冻结分开。
4. 对二手索引做反查并纠正 PixelPrune 作者；未核验 metadata 的条目不承担当下的新颖性结论。
5. 新颖性评估保持开放：不能宣称“多模态没有类似监督”；下一步是寻找与候选视觉教师最相近的工作并设计公平对照。
